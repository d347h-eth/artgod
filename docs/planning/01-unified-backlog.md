# Unified Backlog

This is the single durable ledger for retained ArtGod engineering work. Current
topic documents describe the implemented boundary and preserve important future
design constraints; this file gives that remaining work stable priority and
status. It preserves the historical `BKL-*` identities while replacing stale
plan snapshots with current source evidence and links to the owning domain
reference.

Last broad source audit: 2026-09-13. SQLite storage implementation update: 2026-09-19.

## Status and Priority

- `Open`: the outcome is not implemented.
- `Partial`: a useful subset exists, but the stated remaining outcome does not.
- `Done`: current source and tests cover the outcome; the row remains as history.
- `Superseded`: a later architecture removed the need for the proposed remedy.
- `P0`: correctness or safety; `P1`: core product completion; `P2`: scale or
  reliability; `P3`: longer-term architecture or product depth.

The status is not a promise of release timing. Domain documents describe the
implemented boundary; this file only prioritizes changes to it.

## Maintenance Rules

1. Do not add design essays here. Add current technical context to the owning
   domain document and link to its exact section.
2. Do not mark an item `Done` from a branch narrative. Verify composition,
   persistence, runtime behavior, and tests in current source.
3. If architecture removes the need, mark the item `Superseded` and explain the
   replacement; do not silently delete its history.
4. New items receive the next stable `BKL-*` identifier. Rewording an existing
   item must preserve its underlying outcome.
